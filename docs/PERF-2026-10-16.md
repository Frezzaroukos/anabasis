## Diagnosis and changes

On live, the app LCP element on all SPA routes was the same safety-notice paragraph (`main.mx-auto > div.mx-auto > div.min-w-0 > p.text-xs`). It is text, with no LCP resource-load phase. The landing LCP element is the existing hero dashboard screenshot (`main > div.wrap > div.hero > img.shot-hero`). On a representative `/` run, the live LCP was 3057 ms and the paragraph's render delay was about 163 ms after first content; the remaining wait came from `App` returning only its spinner until `bootstrapDB()` completed.

`App` now mounts `RouterProvider` immediately. The shared navigation, offline area and safety notice paint while IndexedDB opens and bootstraps; `AppShell` keeps route content on its existing loading fallback until `bootstrapDB()` resolves. The database transaction, seed order, OAuth/magic-link sequence and auto-sync startup remain unchanged. A component test checks that the shell is rendered while boot is false, the route content remains gated, and it appears once boot is ready. Candidate LCP still names the same safety-notice paragraph; representative `/` candidate LCP was 2552 ms with about 127 ms element render delay, reducing the baseline median by 649 ms.

The representative `/landing.html` hero image transferred 169,914 bytes (`dashboard.png`) and its following screenshot 80,250 bytes (`calendar.png`); the route median Performance is 99 and LCP did not regress, so these images were left unchanged. The split Recharts chunk (406 KB raw / 109 KB gzip) was absent from the requests on the seven tested routes, confirming existing route/chart splitting avoids loading it here. On representative route runs candidate transfer was 14,383 bytes CSS and 51,386–92,547 bytes fonts; shared JS was about 405.7 KB raw / 131.1 KB gzip and the React chunk 229.4 KB raw / 74.7 KB gzip. The candidate serve.py response checks confirmed gzip for HTML and hashed JS, no-cache, must-revalidate for /, and public, max-age=31536000, immutable for hashed assets (matching serve.py lines 21 and 47–50). Asset transfer and existing cache policy were not the limiting cause for the failing live LCP routes, so no font/image/cache changes were made.
